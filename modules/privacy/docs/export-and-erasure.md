# Export and erase a person's data

Use this guide to answer an access, portability or erasure request. You need
the `privacy.requests.export` or `privacy.requests.erase` permission. Both ask
you to confirm it is you before they start.

Nothing is exported or erased until a named person on your team chooses to. The
tool never does either on a schedule, in bulk or on its own.

## Before you start

The request must be open, and its identity check must be **Verified** or **Not
needed**. Otherwise the tool says "Check and record the person's identity
before you start this." Open the request and edit it to update the check.

Export is for access and portability requests. Erasure is for erasure
requests. The server refuses any other kind, even if the screen shows the
button.

## Export a person's data

1. Open the request and find the **Export and erasure** panel.
2. Choose **Export this person's data**.
3. Confirm it is you if asked, then choose **Export this person's data** in
   the dialog.
4. The panel says "The export is being made". It checks again by itself and
   usually takes a few minutes.
5. When it says "The export is ready", choose **Download file**.

The export collects what you hold about the person from every tool, including
tools you have switched off. The field classification map decides which fields
it reads, so a new field is included from the day it ships.

Only you can download the file. It is deleted after 7 days. The panel then
says "The export has been deleted". Start another export if you need it again.
Nothing is sent to the person. Check the file for other people's details
before you send it to them yourself.

If it fails, the panel says "No file was made." Ask the operator to check the
service.

## Erase a person's data

1. Open the erasure request and find the **Export and erasure** panel.
2. Choose **Erase this person's data**.
3. Read the dialog. It says this cannot be undone.
4. Type the person's name exactly as shown. This guards against erasing the
   wrong person.
5. Confirm it is you if asked, then choose the erase button, which carries the
   person's name.

Erasure removes or anonymises personal data in every tool, including tools
that are switched off. It does not delete the person's record. It anonymises it
in place and marks it as erased, so everything that points to it still works.

In this tool it clears the request summary and task titles. It keeps the
request's kind, dates, clock changes and outcome, so you can show you dealt
with it.

The audit trail keeps ids and codes only. It is append-only, so the history
stays true and the erased person cannot be read from it.

When it finishes, the panel says "The person's data has been erased." If it
cannot finish, ask the operator to check the service.

Erasure may conflict with a legal duty to keep records. Ask your data
protection adviser before you start, because it cannot be undone.
