We want as many people as possible to use this service. You should be able to:

- zoom in to 200% without the text spilling off the screen, and use the service
  at a width of 320 pixels
- use all of the service with a keyboard
- use all of the service with a screen reader
- use the service with reduced motion, and in light or dark colours

## How accessible this service is

We aim to meet the Web Content Accessibility Guidelines (WCAG) version 2.2, level
AA. That version includes everything in version 2.1 level AA, which is the
version the regulations name.

We know about some problems. The main ones are:

- an independent accessibility audit has not been done yet
- we have not yet checked every screen with every screen reader, or with older
  versions of iOS Safari
- when you close a tab or reload a page with unsaved changes, the browser shows
  its own warning, which we cannot reword

The [known issues register](known-issues.md) lists every known problem, where we
found it, and when we expect to fix it. We keep it up to date, and we do not
copy it here.

## Technical information about this service's accessibility

[Operator name] is committed to making this service accessible, in accordance
with the accessibility regulations.

### Supported browsers

We design for Safari 16.4 or later, Chrome 111 or later and Firefox 128 or
later. We aim to keep the applicant portal's main journey usable, though
plainer, on older versions of iOS Safari.

### Compliance status

This service is partially compliant with the Web Content Accessibility Guidelines
version 2.2 level AA, because of the known issues listed in the
[known issues register](known-issues.md).

Each tool below has its own compliance status.

### Non-accessible content

The content listed below is not accessible for the following reasons.

#### Non-compliance with the accessibility regulations

See the [known issues register](known-issues.md). It lists each problem with the
WCAG success criterion it affects.

#### Disproportionate burden

We have not claimed a disproportionate burden. If we do, the register will say
so against the row, with the reasons.

#### Content that is not within the scope of the accessibility regulations

Content you upload, such as supporting documents and attachments, may not be
accessible. We do not edit what applicants and staff upload.

## What we are doing to improve accessibility

- We run automated accessibility checks (axe) on the main pages in Chromium,
  Firefox and WebKit. We run them at desktop width, at 320 pixels and at 200%
  zoom.
- We check how pages announce themselves to screen readers when you move
  between them.
- We plan an independent accessibility audit, and will fix every issue it finds
  at level A and level AA.
- We update the register whenever we find, fix or check something.
